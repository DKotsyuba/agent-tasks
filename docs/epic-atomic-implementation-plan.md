# Epic and Atomic implementation

Reuse the current bounded record, root lock, optimistic version, evidence and review engine. No dependencies, services, Git inspection or read migration.

- Canonical refs: E-001, M-001, A-001 and existing M-001/T-001; Module Atomics use M-001/A-001. Top-level records live in epics/, modules/ and atomics/; embedded Tasks/Atomics remain in their single Module YAML. Epic members contain the sole authoritative lists of Module and standalone Atomic refs. Parent context is computed, never persisted twice.
- Work record revision 1 gains optional/defaulted fields; new allocator writes use revision 2 with every counter required. Legacy empty fields preserve the old semantic review digest; reads never rewrite records. Root allocator owns independent monotonic Module/Epic/standalone Atomic counters; Module owns independent Task/Atomic counters. Legacy revision 1 allocator new counters start at one only while the corresponding inventory is empty. Modern revision 2 missing counters refuse even empty inventories after reserved publication gaps.
- create_epic/title/outcome/criteria/required_checks/lead and create_atomic/title/outcome/required_checks/executor/participants allocate standalone records using Project Allocation version. add_atomic/module/title/outcome/required_checks/executor creates embedded work using Module Version. edit_epic/epic supports ordinary partial intent edits and complete modules/atomics list replacement under Epic Version. edit_atomic/ref edits its intent using owning record Version. Creation and membership are separate explicit writes; creation never promises attachment. Membership may change at any time while the Epic is open; it invalidates old approval and cannot duplicate/dangle or steal another Epic's child.
- No implicit inherited check labels: Project/Epic intent is background; each owner's criteria/checks are actual acceptance requirements. Modules and Epic need independent whole-record review; review_work(ref) adds the purpose-based surface, review_module(module) stays compatible and Module-only. Tasks and Module Atomics have no separate review. Standalone Atomics finish with result/state=done when meaningful result, all required checks and no gaps/blocker exist; this lightweight completion is their acceptance policy. No invented commit is required.
- Epic acceptance requires all noncanceled member Modules currently accepted, member Atomics currently done, own meaningful result/criteria/checks and no blocker/gaps. Accepted Epic basis includes current member semantic bases and acceptance generations; relevant child changes/reopen make approval historical. Cancellation is reasoned and never cascades: resolve member work first. Canceled parents block child writes and reopen is explicit.
- Standalone integration Atomics declare participating Modules plus scenarios (check labels/details). A result captures current Module semantic bases, including current review generation (a new review also invalidates prior integration); changed participants make done evidence stale and prevent Epic acceptance. Refresh result explicitly; no live Git/source query.
- Context/status/search include all entities exactly once, parents, Atomic/Task counts, leads/results, current acceptance and named missing/unreadable work. Snapshot continuation binds selected view and dependency/parent evidence, while Epic and standalone integration Atomic write Versions also bind direct and transitive dependency observations; owning Module Versions stay whole-file tokens. Healthy owners retain context with PARTIAL coverage and may detach unreadable dependencies through a guarded owner-only write. Existing budgets, partial coverage and outcome-preserving renderer remain.
- New allocation still reserves durable IDs before no-clobber publication: partial effects retain the reserved gap and exact effects; lost/uncertain replies require context inspection before another mutation.

Verification: focused model/storage/tool tests plus real stdio tests in isolated temporary roots; preserve existing demo/real roots. Final full gate and local commit coordinated with root.

Limits: check/artifact/actor content remains reported evidence; no source/Git/runtime inspection or identity authentication is added.

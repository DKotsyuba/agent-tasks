# On-demand progress observer

The runtime has four responsibilities: agreed flat plan/storage, immutable read-only Git evidence, Agent Run admission/result attribution, and compact rendering. No legacy work hierarchy or developer-maintained completion state is loaded. Source history and old installed state remain independent.

## Plan and repository identity

One active plan belongs to a canonical Git common directory; linked worktrees share it and separate clones do not. A plan stores goal, stable internal outcome IDs, CAS revision, integration ref and initial refs/drafts. Re-saving identical intent is a no-op. Owner-agreed scope revisions preserve retained IDs and the original baseline. A genuinely new agreed plan captures a new baseline and archives the previous goal/scope/last compact summary.

Original per-call host metadata captures creator_address automatically. A normal revision preserves the original creator; new_plan captures the new creating agent, and archives retain their original contact. Configured Bridge host/store mapping (default local/codex-main) builds the canonical contact address. Missing metadata stays unknown. This is a contact, not native attestation, current reachability or source/admission authority; model arguments and persistent server environment never supply a plan creator.

## Immutable evidence

Collection observes local branch/detached-worktree tips, deduplicated commit messages, endpoint changes/current content and eligible staged/unstaged/new text. Active developer worktrees are prioritized before bounded historical branches; remaining branch selection prefers recent commit times. Oversized aggregate diffs retain bounded per-file patches, prioritizing implementation source over documents. Candidate patches use merge-base-to-tip changes, so older branches do not fabricate deletions of newer target files. Large draft text retains explicitly incomplete head/tail excerpts under the shared evidence budget. Race validation reuses the original bounded draft allowance rather than interpreting a spent content budget as a source change. Initial drafts remain distinguished from subsequent work. Current target content takes precedence over historical ancestry: an unchanged retained branch cannot undo a target revert. Incompatible branch fragments do not form a synthetic completed tree.

Missing objects, inaccessible worktrees, concurrent changes and bounded omissions are explicit. No status operation fetches, switches branches, merges, tests or writes source. Git commands disable external helpers and inherited repository overrides. Runtime records supplement Git only when their workdir maps to this repository; analyzer work is excluded. Current active executions and recent successful handoffs precede old failed runs. Failures older than this repository's active execution episode remain outside the selected current context, with explicit selection omissions. Recent block tails prioritize actual test/command results over large source-reading output. Successful worker answers are included only after sequence/hash fencing; verified retained answer bytes do not independently certify their code or test assertions. No runtime observations means unknown activity, not idle development.

## Analysis and recovery

Before submission, the per-repository atomic record owns the entire immutable start request, original caller namespace/binding, request key and input digest. Reply loss replays this exact intent, including from a different requesting chat. A confirmed terminal failure permits a later explicit status request to create a new generation; uncertain admission never does.

The adapter uses the existing local Agent Run socket. The first request returns a cached compact report or a durable pending handle. With optional Bridge settings, a pending result requires no agent follow-up: a one-shot child event-waits on the public wait API, validates the original execution and sends the compact report through the pinned Bridge SDK. This analyzer is unbound, suppressing redundant lifecycle notices. Without Bridge, the existing bound completion notice triggers one explicit pinned result read; unbound hosts recover on the next explicit request. Analyzer executions are never resumed.

The child inherits an already-held completion file lease as stdin, has null output pipes and its own process group, and survives normal MCP EOF. It releases the repository transaction while event-waiting. Lease release precedes a live repository-lock release on success and error. There is no progress sampling or new resident service. Interrupted socket waits retain the original admission and a safe failure class; a later explicit request can recover. Unknown admission replays its exact saved key automatically once, preserving the original destination even if the analysis has already finished.

One delivery record freezes original deployment, dedicated credential association, destination and event key before admission. Final report/body/hash and cleared admission are one atomic transition; undelivered custody survives report eviction and blocks replacement publication. A possible SDK write is saved before sending. Lost acknowledgements permit one immediate same-event status read; unknown publication remains sticky even if that read fails. A later explicit request reconciles the original event only, with no changed message, address or model launch. Confirmed terminal/invalid analyses publish a classified failure instead of fabricated progress. Bridge owns native dispatch after exact producer/destination/hash custody checks. Custody does not prove arrival or reading, and native message delivery may wake a host turn.

Results must match the original sequence before and after verified answer retrieval, the answer digest, immutable input identity and plan revision. Closed model rows must cover exactly the agreed IDs and cite only supplied evidence. Rust computes totals. Draft/message-only claims cannot establish committed implementation. Successful test applicability requires a matching checked content identity; otherwise it remains reported/historical/unknown.

## Compact presentation and retention

The report is a localized bullet list (Russian by default, English optional): a bar, implemented/total and in-progress counts, unique observed new commits, at most three concise outcome descriptions separating local completed work from the remaining condition, integrated/total and change from a comparable previous report. Commit references are deduplicated across supplied Git evidence; any Git omission makes the count a lower bound. The `[summary]` language and bounded optional style prompt are frozen in the input and cache identity. Late/pinned reports keep their original preferences. Custom wording never replaces the schema, evidence rules or deterministic counters/layout. All service messages, including pending and plan metadata, remain English. New model rows require a short owner-facing title and a remaining condition for unfinished work. Older retained reports and pending requests keep their original row contract. A locally completed sub-block does not close a broader plan outcome. One optional attention line preserves a consequential uncertainty/deviation. Counts refer to distinct outcomes, not agents, commits or hours. Clock passage cannot establish uninterrupted stagnation or its cause.

Retain the baseline, the latest two successful reports with their supplied evidence, and one pending calculation. Results remain pinned to their original revision even when scope changes during inference; they never become evidence for a new denominator. Evicted detailed handles return snapshot_expired. No historical detail read silently recollects current files.

Each successful record also retains the exact submitted model task, including its schema and previous comparison context. Evicting an earlier report therefore does not erase input data supplied to a still-retained result. Detail metadata reports its byte size without expanding the compact owner view.

Detail responses are at most 64 KiB. The combined outcome/finding/source-index page returns at most 32 rows and a `page.next_start` continuation. Supply the retained `analysis_id` and `start` for subsequent pages, or `evidence_id` for an exact saved source. Detail reads without a handle select the latest successful report and never trigger collection or inference.

Cache identity includes plan/evidence/route/profile/prompt semantics, excluding observation clocks, elapsed/silence values, notification state and analyzer telemetry. New developer evidence or actual code/state/coverage changes invalidate it. Retention happens during explicit requests; no watcher, scheduler, database or background summarization exists.

## Qualification boundary

New behavior remains not_verified until actual gates pass. Normal tests use synthetic Git repositories and a fake socket with explicit synchronization. Ignored real-provider tests submit once, retain their fixture, and perform one result read after actual completion. Semantic qualification includes misleading commit messages, partial implementation, drafts, unrelated changes and retained-branch reverts. A finite passing sample is not a guarantee of perfect inference.

The progress-summary role file is a deployment candidate, not installed policy. Effective permissions/global MCP caps, configured model suitability and the actual owner status/notification/result flow need qualification before activation. No live global configuration, old data, source main, installation or publication is changed by building this candidate.

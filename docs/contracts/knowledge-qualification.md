# End-to-end qualification: production matrix against the pinned provider artifacts

Status: planning artifact for Module M-006 (qualification, real SDK protocol tests, canonical skills, code-adjacent documentation). Nothing here is implemented or passed. The source baseline is the accepted installed hotfix `e971dac` (0.9.2). Every row is written against the actual text of the pinned provider artifacts, never a presumed API. [architecture.md](../architecture.md) stays the truth for implemented behavior.

Owner decision applied: the MCP commits automatically after every successful actual change of a work, knowledge, document or compaction record. Reads, true no-ops, refused calls and partial or failed calls produce no commit. The earlier matrix assumed a policy that never commits and an open trigger decision; both are obsolete and removed.

## 1 Pins

M-006 provides no runtime boundary. It consumes two canonical entries (`kr-operations` r7 and `registered-tool-surface` r5) and reads the current artifacts of four further providers. Pins state the agreed behavior at agreement time. They are not a rule that the source documents keep these digests forever: a legitimate later revision is re-pinned by a new agreement, and no test compares document digests. Artifact headings carry a semantic revision (for example "revision 3" inside the knowledge text) that is distinct from the tracker entry revision; this document always uses the tracker revision.

## 2 Real surface and suite rules

Tools under test (registered surface, section 2 of the surface artifact): the existing ten plus `knowledge_work` (M-001), `document_work` (M-002), `compaction_work` (M-005) and `git_recovery` (M-004). Reads add no tool: `get_context` (refs D, RB, RS, CL, CL/I, DOC, paths, CP, with views `history`, `references`, `content` and selectors `ordinal`, `heading`, `occurrence`, `level`, `preamble`), `project_status` and `search` (`kinds`, `state`).

- Real surface only: the shipped binary through the SDK stdio client (`MCP_TEST_BINARY` or the Cargo binary), `env_clear`, disposable HOME, config and registry, no inherited credentials, no network, no real project data. Versions are read through the MCP, never derived. The existing `connect` and `call` helpers are reused; a reply is checked for text only, one content block, at most 8192 bytes in total.
- The crate is binary only. Tests under `tests/` cannot reach `cfg(test)` code: `DeferAll`, `with_policy`, `fail_at` and `GitFixture` exist only in M-004's in-crate tests, which M-006 neither re-implements nor calls. There is no flag, variable, feature or configuration that selects a policy or injects a fault in a shipping build, and none is added for qualification.
- Fault levers available to a real-process test, none of them a product switch: repository hooks (a failing pre-commit or commit-msg, a hook that edits a file, a slow hook for the 10 second command timeout, a hook that kills the server process during settlement, which runs after the handler returned, so it models a crash during the commit only and never a crash inside a handler), repository configuration (signing enabled with an unusable key), files the test writes natively (an index lock, a merge marker, a native edit of a published file, a staged foreign file on the same path or a neighbor), read-only target directories (a real failure after the first publication), detached HEAD and a nested repository. Restarting the server after such a kill gives a real crash-during-commit and reconciliation scenario. A crash inside a handler or right after a rename is not reachable through a real process without a product switch; it stays with M-004 in-crate fault points. Interrupted multi-step operations (a compaction apply, a document save with its record) are produced by a read-only target parent that fails the later step after an earlier one published, then restoring the permission and repeating the same call.
- Read and lookup operations are checked with a tree snapshot (relative path, kind, length, sha256, modification time in nanoseconds) of the documentation root, the git directory and the config directory before and after, plus an empty staged index difference. A new file, lock, directory, changed time, index entry or commit fails.
- Byte exactness is asserted on bytes: native file bytes before and after, decoded reply text against the original, never an excerpt.
- Budgets: replies are measured at 8192 bytes TOTAL, including header, framing and footer, never a per-page payload claim. Exhaustive page-budget loops and large pure sweeps belong to M-002's module tests (the suite requires the named test to exist, pass and have its mutation record). The SDK uses representative budgets and sizes at the boundaries: 0, 1, 8191, 8192 and 524288 bytes for a document, 524289 refused, a few full reads of the maximum document in about 70 pages each, and deadlines per scenario well under the 600 second whole-test budget.
- Each meaningful boundary has correct-pass, mutant-fail and restored-pass on the same cases, tied to the restored candidate and the pinned entry revision, recorded with `boundary_evidence`. A mutant is a deliberate edit of product source in an isolated worktree, described as a reviewed patch with its expected failing case, applied and reverted only there and never committed.
- One shared legacy fixture, `tests/fixtures/legacy-docs/`: a frozen copy of the 11 files of `docs/` at the base commit (199684 bytes, ASCII and UTF-8, LF only), also usable by M-002. The live `docs/` is never the fixture because it changes with this Epic.
- Registration and signing: fixtures run with an environment that carries no signing agent. Signing failure is exercised through repository configuration, never by weakening an owner's signing policy.

## 8 Acceptance gaps and machinery check

Required before acceptance:

1. Every read is writeless by the tree snapshot, including pending facts and `read_cp`.
2. The reply states `wire`, byte range and `encoded_len`; the suite decodes with only those.
3. Continuation is stale after any change to body, record or selection; adopt of identical bytes also stales an in-flight read (conservative, documented).
4. Same-path and neighbor foreign staging and hooks are preserved in real repositories.
5. Immutable originals and revisions survive Git deferral; compaction typed bodies are never sources; partial incoming coverage blocks every destructive step.
6. Provider ports that are not yet implemented are not substituted in end-to-end rows. Provider-level substitutes stay inside the provider's own tests and never count as composition proof.
7. Registration is never settled again and is excluded from the commit count.

Machinery to challenge: five recovery actions (justify retry, adopt and release with a failing scenario each), device and inode evidence in the journal (diagnostic only), and the size of the compaction record with full prior bodies retained (r3 refuses an overflowing revise before any effect).

## 9 Lexical search quality plan

Measurement precedes any semantic proposal; no embedding service is in scope.

- Record per query: hits, rank of the first expected, recall at 5, missing references, coverage per source, reply bytes and calls needed to open the hit by its exact route. Output one table, not a pass label.
- Misses are classified. Defect: expected term present and not found, or complete coverage claimed with a gap. Vocabulary gap: no shared term. Only vocabulary-gap rows can motivate semantic retrieval, and their threshold is the owner's later decision.
- Honesty: every source states complete or PARTIAL; the unsupported name is quoted; ranking is stable across reruns; every hit has a working read route.
